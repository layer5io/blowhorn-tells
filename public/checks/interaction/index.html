Interaction

A short task on the tool page. It shows how a click and a keystroke arrived, not what was typed.

What this check is

The interaction test is a three-step task on the tool page: press Start, click the field and type the phrase tells check 42, then press Submit. A person finishes it in under 20 seconds. Start and Submit can also be pressed from the keyboard, with Enter or Space after Tab has focused them. The phrase is fixed, so nothing you type is read, sent or stored.

What Tells reads

  • The order of press and release events on the Start and Submit buttons
  • Whether each button was pressed with the pointer, or with Enter or Space from the keyboard. A keyboard press has no pointer position, so the pointer checks are not judged for it
  • Where on each button the pointer landed, and the offset between screen and window coordinates
  • How far the pointer travelled in the second before each press, counted in pixels, never as a path
  • How long each press and each key was held, and the gaps between keys
  • Whether the text arrived as typed keys, as pasted text, or as text with no key presses
  • How long the task took from Start to Submit

Only counts, timings and the order of events leave the page. The key values, the typed text and the pointer path are never kept.

How to read your result

  • Pass: The task was completed and the evidence matched a person.
  • Warning: The task was completed and something was unusual, such as a paste, a missing key event, or screen coordinates equal to window coordinates on every click.
  • Not available: The task was not taken, or no check could be judged on it. That is a neutral result; the verdict is computed without it.

Provisional. While the thresholds are uncalibrated, the check is warn-only. A failing check is still shown in its results and adds a medium note to the verdict, but it never makes a verdict bot on its own, and the most the 13 checks can take off the score is 39 points. A warning adds a low note. When calibration on 20 or more human runs is done, a fail becomes a high note; that change is one line in the Worker.

Script-made input is scored once. The Remote-control tells check counts every script-made input event on the page, this task's included, as its own reason. When it has, int_trusted still shows its fail in the results but adds no second penalty.

Why it matters

Passive signals sometimes cannot separate a careful script from a person, and a small, observable task can. The interaction test is deliberately gentle: no identity, no real data, nothing stored. What it measures is the manner of the input, never the content.

Where this matters most

Across the platforms Blowhorn works with, rated in the platform guide (H = matters a lot, M = contributes, L = no public evidence; tags mark vendor-stated, reported, or inferred evidence):

  • LinkedIn (H): checkpoint and identity verification is the standard consequence of a restriction [Vendor]
  • X (H): Arkose challenges gate account unlocks and sensitive actions [Reported]
  • Reddit (M): flagged accounts face human-verification challenges [Reported]
  • GitHub (M): CAPTCHA and verification appear at signup and on flagged logins [Reported]

Everywhere else in the set this one rates Low.

In your report

Find it in the checks table on the tool page, with the task in the interaction test panel. The report JSON carries the interaction report under client.interaction and the scored reasons under verdict.reasons, with ids such as int_centre. The agent guide explains how to read them programmatically.
